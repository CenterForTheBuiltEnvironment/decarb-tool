# Testing Scheme — Berkeley Decarb Tool

## Purpose

1. **Show the numbers are right.** Energy and emissions results are checked against
   independently calculated values (hand calculations, an independent re-implementation, and
   the team's earlier hand-calculation spreadsheet).
2. **Catch changes.** Any change that moves results, intended or not, fails a test, so it gets
   reviewed instead of slipping through.
3. **Catch workflow/UI breakage** without a browser: broken pages, callbacks wired to missing
   components, charts or downloads that crash.
4. **Need little upkeep.** Verification cases own their inputs, expected values are written as
   formulas, regression baselines regenerate with one command, and chart options are read from
   the live layout.

Run everything with `python -m pytest` (about 90 s; all tiers except `app` finish in ~5 s).

## Tiers

Every test carries exactly one tier marker. `tests/conftest.py` fails collection if a test has
none, because CI selects by marker and an unmarked test would silently never run.

| Marker | Files | What it proves | Data | Time |
|---|---|---|---|---|
| `unit` | `test_energy_unit.py`, `test_loads.py`, `test_equipment.py` | Helper functions: interpolation, capacity limits, COP lookups, load validation | synthetic | <1 s |
| `verification` | `test_verification_handcalc.py`, `test_verification_reference.py`, `test_verification_spreadsheet.py` | Results match independently calculated values | test-owned equipment; real loads/Cambium for the reference model | ~2 s |
| `regression` | `test_energy_regression.py`, `test_loads.py::TestGetLoadData` | Energy balance invariants; hourly energy and emissions snapshots | real library, 24 h synthetic load | <1 s |
| `integration` | `test_energy_integration.py` | Full-year runs: invariants plus golden annual energy and emissions totals (±0.1 %) | real parquet + Cambium | ~2 s |
| `app` | `test_app_smoke.py`, `test_workflow.py` | Server, pages and callback wiring; headless end-to-end Results workflow | real | ~85 s |

### Verification

**Hand calculations** — `test_verification_handcalc.py`. An 8-hour load profile and round-number
equipment defined in `tests/verification/equipment.py`, *not* the production library. Each
hour isolates one mechanism: AWHP at catalogue points, linear interpolation, operating limits,
backup pickup, the heating/cooling compressor split, sizing with redundancy, constant-rate
electricity, gas and refrigerant emissions, and fuel switching. Expected values are written as
the arithmetic, e.g. `120 / 2.5 + 100 / 2.0 + …`.

**Independent reference model** — `tests/verification/reference_model.py` re-implements the
method documented in `docs/documentation/calculations.md` using only numpy/pandas and the raw
data files. It never imports `src/`. `test_verification_reference.py` compares annual
electricity, gas and emissions for buildings 83 (hospital, NY) and 35 (large office, SF)
× `eq_scenario_1/3/4` × constant and Cambium long-run grid
rates: 72 comparisons, tolerance 0.001 %. Scope is deliberately narrow (no heat recovery, no
fuel switching) to keep it cheap to maintain; the module docstring lists the method details the
user docs leave implicit.

**Legacy hand-calculation spreadsheet** — `tests/testing_cases.xlsx` (7 scenarios × 3
characteristic hours, 3 buildings; kept locally and git-ignored) is frozen into `tests/fixtures/spreadsheet_cases.json` by
`python -m tests.verification.extract_spreadsheet`, *including the equipment data it assumed*
(which has since changed in the library). The committed JSON is the source of truth for the
tests; the spreadsheet is only needed to re-extract it. `test_verification_spreadsheet.py` replays each case.
Values are tagged in the fixture as:
- **checks** — asserted within 0.2 % (the spreadsheet rounds COPs to two decimals);
- **superseded** — computed with a rule the tool has since replaced (AWHPs that are heating did
  no cooling at all; now the idle compressors can cool). Not asserted; the new rule is covered by
  the hand-calculation tests;
- **known differences** — open method questions, run as strict xfails (see below).

**Report** — `python -m tests.verification.report` prints the tool-vs-reference table and
the spreadsheet agreement summary, generated by the same code the tests run
(`--csv out.csv` writes the full comparison).

### Regression

`test_energy_regression.py` runs four library scenarios (plus `eq_scenario_18` for fuel
switching in the emissions snapshot) on a 24-hour synthetic profile spanning the AWHP
operating limits. It checks energy balance invariants and compares the full hourly output with
syrupy snapshots in `tests/__snapshots__/`.

### Integration

`test_energy_integration.py` runs buildings 83 and 35 × `eq_scenario_1/3/4/5/10/18` (baseline,
partial and full AWHP, heat recovery, fuel switching) through the same call chain as the
Results page, using the app's default emission scenarios (Cambium MidCase long-run, 2025/2035/2045).
It checks hourly invariants (no NaN, loads fully served, component sums, emissions sums) and
annual totals against `tests/snapshots/integration_annual_totals.json`. A measured building
(182: gaps, leap year, two calendar years) runs as a smoke case.

Golden values are regression anchors, not truth; the verification tier is the truth check. A
missing golden entry **fails** (it used to skip, which would hide gaps in CI).

### App (workflow and UI)

- `test_app_smoke.py` — `/`, every page path, `/_dash-layout` and `/_dash-dependencies` respond;
  every page layout renders and serialises; every component id a callback reads or writes exists,
  either in a layout or as a literal `id="…"` in the source (covers components built at runtime);
  no output is written by two callbacks unless marked `allow_duplicate`.
- `test_workflow.py` — calls the real Results callbacks as plain functions with the stores a
  user would have filled in: the auto-calculation (`initialize_results_page`), every chart in SI
  and IP, and the ZIP export. It covers every predefined equipment scenario group, all four grid
  emission sources, a measured building, a custom CSV upload, and rejection of negative loads.
  One test sweeps every option of every chart control; the options are read from the live
  layout.

## Known issues pinned by tests

These are deliberately encoded so they stay visible. A strict xfail turns red as soon as the
behaviour changes, prompting you to remove the marker.

| Test | Issue |
|---|---|
| `test_verification_spreadsheet.py::test_known_method_differences` | AWHP sizing at a non-catalogue HHWST (42 °C) uses the nearest table (38 °C) for the reference capacity; the spreadsheet interpolates. −0.3 % units. |
| `test_energy_integration.py::test_measured_scenarios_cover_the_same_hours` | On measured data, hours with missing outdoor temperature become NaN for AWHP scenarios but not boiler/chiller ones, so scenario annual totals cover different hours (building 182: 16 vs 648 NaN hours). |
| `test_app_smoke.py::KNOWN_ORPHAN_IDS` | `results_page.show_project_summary` writes to `summary-project-info`, which no layout renders. |

## CI

| Where | What runs |
|---|---|
| pre-commit (`.pre-commit-config.yaml`) | `pytest -m unit` (≈1 s) after ruff |
| `.github/workflows/tests.yml` | full suite on pushes to any branch except `main` and on PRs into `development` |
| `.github/workflows/deploy.yml` | full suite on pushes/PRs to `main`; deployment only runs if it passes |

The `cloudbuild.yaml` test step from the earlier `#132-testing-scheme` branch was not ported:
`deploy.yml` builds with `gcloud builds submit --tag`, which ignores `cloudbuild.yaml`.

## Playbook

**A snapshot or golden test fails after a code change.**
1. Decide whether the change *should* move results. If not, it's a bug: fix the code.
2. If it should, regenerate and review what moved:
   - `pytest -m regression --snapshot-update`, then `git diff tests/__snapshots__/`
   - `pytest -m integration --generate-golden`, then `git diff tests/snapshots/`
3. Check that the verification tier still passes. If a verification test fails, the change
   contradicts an independent calculation. Don't "update" it; find out which side is wrong.
4. Commit the regenerated files with a message explaining *why* results moved.

Adding a new output column changes every regression snapshot. That's expected: confirm the diff
only adds the column.

**A verification test fails.** Treat as a real discrepancy. If the method has intentionally
changed, update the hand calculation or reference model *and* the documentation
(`docs/documentation/calculations.md`) in the same commit.

**Equipment library edited.** Verification is unaffected (it owns its equipment). Regression and
integration may move; follow the snapshot/golden steps above.

**New equipment scenario or group.** The workflow test picks up new scenario groups
automatically. Add the scenario to `SCENARIOS` in `test_energy_integration.py` if it exercises a
new engine path, then regenerate golden values.

**New chart option.** Nothing to do: `test_workflow.py` reads options from the layout.

**New engine phase or method change.** Add a hand-calculated hour to
`test_verification_handcalc.py` showing the new behaviour, written as arithmetic.

**Spreadsheet corrected.** With the local `tests/testing_cases.xlsx` in place, rerun
`python -m tests.verification.extract_spreadsheet` and review the JSON diff.

## Not covered yet

- **Browser end-to-end** (Playwright): one happy-path click-through Loads → Equipment →
  Emissions → Results, asserting no error notifications and no browser console errors. Run nightly
  rather than per push. This would add coverage for clientside callbacks and component rendering,
  which the headless tests cannot see.
- **Reference model scope**: heat recovery (HR-WWHP) and fuel switching are verified by hand
  calculation and the spreadsheet, not by the full-year reference model.
- **Method validation** against EnergyPlus or measured plant data. The verification here shows the
  tool implements its documented method correctly; it does not validate the method's
  simplifications (no fan/pump energy, no part-load or defrost derates).
